# Розрахунок реакції

`ReactionCalculator.calculate(catalog, reaction_id, mixture)` повертає `ReactionCalculation`. Це чистий розрахунок однієї явно обраної реакції, без зміни суміші, подій відкриття чи візуальних ефектів. Вибір між кількома реакціями й застосування результату ще не реалізовані.

## Перевірки та результат

Розрахунок працює з валідованим ReactionCatalog та водними компонентами MixtureState. Він відхиляє відсутній каталог/суміш, порожню суміш, невідомі компоненти, непідтримувані фази реагентів, невиконані температурні й концентраційні умови, відсутні реагенти та числові переповнення.

Коди: `ok`, `invalid_input`, `unsupported_reaction`, `empty_mixture`, `unknown_species`, `unsupported_phase`, `conditions_not_met`, `insufficient_reagents`, `numeric_error`. Непідтримувана реакція не означає неможливість реакції в реальному світі.

Алгоритм: для кожного реагенту обчислити n/nu, взяти мінімум xi, витратити xi*nu реагентів і утворити xi*nu продуктів. Перевірені умови беруться з даних; гра не вигадує температурні чи концентраційні пороги. Межі температури включні. Концентраційний поріг також включний, без прихованого послаблення.

Знімок успішного результату містить:

- `reaction_id`, `mixture_revision` — контекст розрахунку;
- `extent_mol` — ступінь проходження реакції в mol;
- `limiting_species` — відсортовані ID лімітуючих реагентів;
- `consumed_mol`, `produced_mol` — кількості витрачених/утворених компонентів;
- `product_phases` — фази продуктів із каталогу;
- `remaining_dissolved_mol` — вихідні розчинені компоненти після віднімання реагентів, БЕЗ додавання продуктів.

Останнє поле не є кінцевою сумішшю. Майбутня операція застосування повинна окремо врахувати водні продукти, осад, газ і утворений розчинник, перевірити актуальний стан та запобігти повторному коміту. Саме поле revision ще не є повним захистом від повторного застосування або використання результату для іншої посудини.

Відносний допуск 1e-12 застосовано для повідомлення про практично однакові лімітуючі співвідношення та корекції лише незначного переповнення витрати через округлення. Він не задає мінімальну кількість речовини. Нульові реагенти відхиляються; малі додатні кількості підтримуються, доки розрахунок представляється числовим типом. Результат повертає глибокі копії; повторний розрахунок сам по собі не витрачає реагенти.

## Перевірка

Після імпорту класів запустити Godot із `--headless --path . --script res://tests/run_reaction_tests.gd`.

Перевірено 54 твердження: умови й межі, лімітуючий реагент, надлишок, коефіцієнти 1:1 і 2:1, масштабування рівняння, газові продукти, сторонній іон, баланс атомів/заряду, малі кількості, числове переповнення, ізоляція результату та незмінність суміші.

Використано тестові визначення, не готовий каталог гри. Подальша поведінка карбонату при неповному підкисленні, рівновага й інші багатоступеневі явища тут не моделюються. Алгебраїчний тест не є підтвердженням фізичної точності сценарію.
